# Оценка смещения датчика по гироскопу после захвата — 30.10.2026

## Алгоритм

PID сначала наводит объект по измеренному углу. Пока модуль исправленного угла
не удерживается меньше 1° непрерывно 0,2 с, оценка не меняется.
После захвата используется отрицательная обратная связь по сглаженному CurrentW:

```text
filteredW += (1-exp(-dt/0.15)) * (CurrentW-filteredW)
biasRate = clamp(-0.6 * filteredW, -20, 20)
estimatedBias = clamp(estimatedBias + biasRate*dt, -45, 45)
error = Wrap(MeasuredAngle-estimatedBias)
W = Kp*error + I - Kd*CurrentW
```

Изменение estimatedBias выполняется только после захвата и при
abs(filteredW)>0,1°/с. При меньшей скорости оценка сохраняется; если скорость
снова выросла, подстройка возобновляется. Это допуск около нуля, а не проверка
точного равенства вещественного числа нулю. При потере захвата подстройка
приостанавливается; для возобновления снова нужна выдержка 0,2 с.
Коррекция уже найденным значением продолжает действовать и вне захвата.

На первом вызове коррекция не адаптируется. PIDreset сбрасывает оценку,
выдержку, фильтр и историю измерения, сохраняя настройки и флаг включения.
При выключенном флажке оценка сохраняется, но не вычитается из угла.
Настройки PID 3,87/22,88/0,10 и ограничение I=20°/с сохранены.
Пределы поправки: ±45°, скорость изменения не больше 20°/с.

В интерфейсе восстановлены флажок «Оценка смещения датчика» и вкладка
«Адаптация». Показаны оценка и состояние подстройки/удержания. Неиспользуемые
BiasAngularSpeedWeight и DerivativeFilterTime недоступны для редактирования.
BiasAdaptationStart теперь означает выдержку непрерывного захвата, а не
время от начала симуляции. Старые INI могут содержать другие пороги и нулевой
BiasAdaptationGain — поэтому подготовлен отдельный запуск с новым пресетом.

`MeasuredAngleRate` вычисляется по исходному входному углу и предыдущему dt.
Изменение поправки не влияет на эту производную. Она по-прежнему диагностическая.
Экспериментальное выражение teta заменено оценкой постоянного смещения:
оно использовало прежний CorrectedAngle вместо нового измерения.

## Почему такой знак и когда оценка имеет смысл

В модели измерение = истинный угол + смещение датчика. При захвате
измерение − оценка ≈ 0, поэтому истинный угол ≈ оценка − смещение.
Для неподвижной цели и движения вперёд вдоль корпуса скорость линии
визирования имеет знак истинного угла. Удерживающий цель объект вращается
в том же направлении. Поэтому оценка меняется против CurrentW.
При истинном смещении +7° ожидаемая оценка +7° и её вычитание из измерения.

Это условная оценка, не универсальная идентификация датчика.
Предполагаются неподвижная цель, поступательное движение вперёд без сноса
и согласованные знаки датчика/гироскопа. Из одного угла и скорости вращения
нельзя отличить монтажную ошибку от движения цели или бокового сноса.
Если объект не движется поступательно, он может удерживать смещённое
измерение на нуле с CurrentW=0 при любой монтажной ошибке: информации для
оценки нет. Нулевой CurrentW сам по себе не подтверждает калибровку.
EDF-профили со скольжением и шумом для этой оценки отдельно не настроены.

До пролёта мимо близкой цели CurrentW не обязательно успевает стать нулевым.
Условие нулевой скорости используется для паузы подстройки, но математическая
сходимость до встречи не гарантируется. Расстояние/истинное смещение модели
в алгоритм PID не передаются и для подстройки не используются.

## Проверка

`GyroBiasTest` проверяет первый шаг, выдержку, знак, потерю и повторный захват,
допуск скорости, ограничения скорости/величины поправки, отключение, сброс,
атомарное отклонение некорректных входов и независимость производной угла.
Также четыре замкнутых опыта на рабочей геометрии: старт (0,0), курс 0°,
скорость 200 км/ч, неподвижная цель (261,542189;118,876831) м,
задержка 3 измерения, dt=0,01 с. Истинное смещение доступно только проверке.

| Смещение | Оценка при первом сближении | Минимальный промах без / с коррекцией |
|---|---:|---:|
| −20° | −20,055° | 5,299 / 0,113 м |
| −7° | −7,086° | 1,244 / 0,080 м |
| +7° | +7,005° | 1,238 / 0,217 м |
| +20° | +20,074° | 5,299 / 0,226 м |

Дополнительно 135 проверочных сценариев: неподвижная цель в 300 м,
начальные направления −30/0/+30°, смещения −20/−7/0/+7/+20°,
задержки 0/3/6 измерений, dt=0,005/0,010/0,015 с, скорость 150 км/ч.
Оценивается первый минимум расстояния после начальной секунды движения.
Все вычисления и поправки конечны и остаются в заданных пределах. Этот набор
также использовался для сравнения 0,5 и 0,6 при окончательном выборе настройки;
он не является независимым подтверждением после подбора.

- Средний минимум расстояния: 1,9642 → 0,0970 м.
- Максимальный минимум с коррекцией: 0,3109 м.
- Средняя / максимальная ошибка оценки: 0,0504° / 0,5847°.
- Сценариев с ухудшением промаха более чем на 5 см: 0 из 135.

Результаты дискретной симуляции не означают гарантии для любых начальных условий.
Сырые строки: `profiles/GyroBias-20261030/validation.csv`.

Отдельное сравнение скорости адаптации и фильтра: 320 опытов, включая движущуюся
цель. Большие коэффициенты (1 и выше) часто возбуждают колебания; выбран 0,6
с фильтром 0,15 с. При движении цели 50 км/ч под −45° и истинном смещении +7°
оценка достигает примерно +18,42°: это пример смешения движения и смещения,
даже если промах уменьшается. Файл `gain_comparison.csv` сохраняет и такие случаи.

### Обновлённый рабочий сценарий

К моменту подготовки сборки рабочий INI уже задавал скорость 10 км/ч,
цель (72,577747;30,625570) м, нулевую скорость цели и смещение +7°.
Эти условия сохранены в отдельной сборке. При коэффициенте 0,6:

| Время | Оценка смещения | CurrentW |
|---|---:|---:|
| 5 с | 1,780° | −0,536°/с |
| 10 с | 3,364° | −0,494°/с |
| 20 с | 5,886° | −0,331°/с |

При первом сближении (28,43 с) оценка 6,978°. Минимум по отсчётам
0,0052 м против 0,0618 м без коррекции. При коэффициенте 0,5 вращение
в этом опыте оставалось почти постоянным −0,49°/с; это стало причиной
проверки и выбора 0,6. До встречи точный нуль скорости не гарантируется.
Протокол: `profiles/GyroBias-20261030/current_scenario.txt`.
## Запуск и воспроизведение

```powershell
./tools/test_gyro_bias.ps1
```

Скрипт выполняет семь наборов проверок, два моделирующих опыта и сборку.
Готовый запуск: `Win32/GyroBias/FModel.exe`. Его INI создаётся из рабочего
Debug INI, затем только секция Controller дополняется новым пресетом из
`profiles/GyroBias-20261030/controller.ini`. Сам Debug INI не изменяется.
Повторный запуск скрипта вновь применяет пресет к отдельной сборке.
Старый BiasAdaptationTest проверяет прежнюю адаптацию и не является тестом
этого алгоритма; актуальная проверка — GyroBiasTest.
