# Простой PID с демпфированием по CurrentW — 30.10.2026

Этот отчёт описывает этап без оценки смещения. Последующее дополнение:
[оценка смещения после захвата](GYRO_BIAS_20261030.md).
Подбор SimplePIDTuning выполняется с отключённой коррекцией.

`uPID.PIDupdate` реализует:

```text
e = Wrap(MeasuredAngle)
P = Kp * e
I = clamp(I + Ki * e * dt, -IntegralLimit, IntegralLimit)
D = -Kd * CurrentW
W = P + I + D
```

Ki=0 обнуляет I. При нулевой ошибке ненулевой интегратор сохраняется.
D работает с первого вызова и не зависит от разности углов или шага времени.
Общего ограничения W в PID нет; EDF ограничивает команду в объекте.
Входы проверяются до изменения состояния. PIDreset сохраняет параметры.
Из закона управления убраны адаптация, фильтры и производная угла.
Отдельно рассчитывается диагностическая MeasuredAngleRate (°/с): разность
измеренных углов с переходом через ±180°, делённая на предыдущий dt.
В модели измерение предшествует движению, поэтому именно предыдущий шаг
разделяет два измерения. На первом вызове и после сброса значение равно 0,
HasMeasuredAngleRate=False; со второго вызова признак True. На P/I/D и выход
эта величина не влияет. История измерений хранится отдельно для каждого State.

Старые публичные поля/ключи INI оставлены для совместимости; Bias*,
DerivativeFilterTime и AngleCorrectionEnabled больше не влияют на расчёт.
Поправка всегда нулевая. В интерфейсе скрыты вкладка адаптации и её флажок.

| Параметр | Значение |
|---|---:|
| Kp | 3,87 |
| Ki | 22,88 |
| Kd | 0,10 |
| IntegralLimit | 20 °/с |

Это лучший найденный округлённый набор при описанном критерии и ограничениях,
а не доказанный глобальный оптимум. Он установлен в исходные значения uPID
и отдельную сборку `Win32/SimplePIDTests/FModel.exe`.
Её INI скопирован из текущего Debug-профиля с заменой только четырёх параметров PID.
Существующий `Win32/Debug/FModel.ini` не изменён: он переопределяет исходные
значения программы, поэтому для старого запуска коэффициенты нужно ввести вручную.

Подбор относится к текущему **профилю 0**: мгновенное исполнение угловой скорости,
постоянная поступательная скорость, движение по Fi без сноса −10°.
Изменение кинематики было сделано пользователем до этой доработки и сохранено.
Профили EDF 1–3 требуют отдельного подбора; старые пресеты нового PID не проверяют.

## Методика

Используются настоящие Delphi `PIDupdate`, `TMotionModel.MeasureAngle` и
`ApplyControl`. В угловом опыте цель устанавливается на расстоянии 10 км
в заданном направлении относительно текущего положения объекта. Это позволяет
проверить угловой контур без смешивания его с пролётом мимо близкой цели.
Скорость объекта 1 м/с; его перемещение, поворот и буфер задержки вычисляет модель.
Смещение датчика в этих опытах нулевое.

Обучение: 24 сценария по 8 с — направления 10°, −30°, 10*sin(0,8*t)°,
3*t°; задержки 0/3/6 измерений; dt=0,01/0,015 с.
2400 кандидатов с seed=20261030: каждый четвёртый — широкий поиск,
остальные — изменение одного коэффициента лучшего набора.
Диапазоны: Kp=0,5…20, Ki=0…40, Kd=0,1…0,85. Предел I фиксирован 20°/с.
Ki=0 проверяется отдельно каждый 17-й кандидат.

Нижняя граница Kd=0,1 — явное условие сохранения активного демпфирования.
Предварительный поиск с Ki<=10 и разрешённым Kd=0 выбирал Kd=0:
идеальный объект профиля 0 не имеет инерции привода. Поэтому ненулевое
демпфирование здесь — заданное ограничение, а не найденная потребность объекта.
Большой Kd особенно нежелателен: CurrentW в профиле 0 равен предыдущей команде,
и слагаемое −Kd*CurrentW образует дискретную обратную связь.

Стоимость одного опыта:

```text
J = IAE/(8*S) + 2*RMS_last2s/S + 0.02*integral((W/120)^2)/8
    + 0.002*sum(abs(delta W))/(8*S)
    + 0.2*max(0,peak(abs(W))/120-1)
    + 0.3*max(0,peak(abs(error))/S-1)
S = max(10, abs(initial bearing))
Score = mean(J) + 0.3*max(J)
```

Штраф за скорость 120°/с не является ограничителем команды.
Критерий сочетает точность, скорость реакции и умеренность команды.
Исходный набор для сравнения взят из рабочего INI: 5/5/0,5, I_limit=20.
Оба набора сравниваются с **новой отрицательной обратной связью по скорости**,
а не с прежним положительным знаком D.
Обучающий Score: 0,272868 → 0,066802 после округления.

скорость 200 км/ч, цель (261,542189;118,876831) м, задержка 3, dt=0,01.
Движущаяся цель идёт под −45°. Фиксируется минимум расстояния по отсчётам
до первого удаления после входа ближе 5 м (горизонт 15 с).

|---|---|---:|

Простой PID не оценивает постоянное смещение датчика. Сведение измеренного
угла к нулю не означает нулевой истинный угол при смещении. Геометрические
числа относятся к этой симуляции и дискретному шагу.

## Воспроизведение

```powershell
./tools/test_simple_pid.ps1           # проверки и отдельная сборка
./tools/test_simple_pid.ps1 -Tune     # также повторить подбор
```

Подбор создаёт INI с четырьмя параметрами, CSV и текстовый протокол в
`profiles/SimplePID-20261030`. Без -Tune проверяются текущие исходные значения.
Старый BiasAdaptationTest неприменим: проверяемый им механизм удалён.
